# 0010: Hebrew with Tesseract

Date: 2026-11-20. Status: proposed (M2 task 7; the owner accepts by merging the pull request).

- **Problem.** No PP-OCRv5 recognizer reads Hebrew (decision 0005, spike), and the engine of decision 0009 already has the seam for it (`HebrewReader`: `probe` and `read`).
- **`TesseractHebrewReader`** (`engine/.../ocr`, shared by the JVM and Android) implements `HebrewReader` over the JavaCPP presets of 3b: `TessBaseAPI`, `Init(<models>/tessdata, "heb")`, page segmentation auto, `SetImage` with the decoded `PixelImage` as R, G, B bytes (no Leptonica image is made by our code). The data is `heb.traineddata` from `tessdata_fast` (0.96 MB, pack `hebrew` in `ModelManifest` since task 4).
- **Probe and read share one recognition.** `probe` is the mean word confidence (0 to 1); `read` is the text. The engine calls them one after the other on the same `PixelImage`, so the reader keeps the last page (by identity) and the second call costs nothing. Hebrew without a language takes about 60 ms.
- **Fixed source resolution (300 dpi).** The decoded image has none; without it Tesseract guesses one and prints a line to stderr for every page. With it the `ja-clean` probe is 0.40 (spike: 0.41; it was 0.71 with the guess, close to the threshold 0.8), so the setting also keeps the probe where the spike measured it.
- **One `TessBaseAPI`, opened on first use and kept until `close()`** (`OnDeviceOcrEngine.close()` now closes the Hebrew reader too). Tesseract is not thread safe, so calls are serialised with a lock. A missing `heb.traineddata`, a failed `Init` or a failed native load is an `Outcome.Failure` with a message, not an exception.
- **Tests.** Unit: the pixel to byte conversion, and the failure without the data file. Opt-in with the real 1 MB data (`GLYPHDRAFT_NETWORK_TESTS=1`): `FixtureHebrewTest` (Hebrew page 0.0 % CER, probe 0.92; the ten other fixtures probe 0.18 to 0.50, all below 0.8) and `he-clean` in `FixtureEngineTest` (Hebrew with and without a language: right language, 0.0 % CER; the other nine still right with the Hebrew pack installed, so the probe does not steal a page).
- **Not handled.** Android: not yet run on the emulator (the engine is not in the app before task 8; the same code loads there per 3b, reading an image is checked by the integration tests of task 8). Windows only: Tesseract opens the data folder with a narrow-character path, so a user name with non-Latin letters in the data folder path may fail to load; unverified, to be checked in the hand test (task 10). Mixed Hebrew and Latin text, and right-to-left text mixed with numbers, were not tested; the page is returned as Tesseract reads it.
