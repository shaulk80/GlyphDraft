# 0009: Language detection and the on-device engine

Date: 2026-11-20. Status: proposed (M2 task 6; the owner accepts by merging the pull request).

- **Problem.** The engine has to choose a recognizer when the user gives no language, and tell the language of what it read (`RecognitionResult.language`). Decision 0005 named Lingua restricted to our languages, with a small own detector as the alternative if its size is a problem.
- **No Lingua; own detector in two steps** (`engine/.../language`, shared code, no model file). Step 1, script: the letters of the text are counted by Unicode block (`TextScripts`); kana make a text Japanese, Han without kana is Chinese, the script with most letters wins. `Language` got a `script` field for it (promised in 0006). Step 2, only where one script has several candidates (Latin: English, German, French, Spanish): `LatinLanguageScorer` counts common words, marker letters (ä ß é ñ ¿ ...) and apostrophe forms (`l'`, `it's`) from lists written for this project; no marker or a tie is "cannot tell" (null). Why not Lingua: its only release on Maven Central (1.2.2, 2022-08) is one 80 MB jar with 75 languages' models for the four we read, with no way to ship only some, and our APK and app image are small by comparison. Cost of the own detector: it needs a sentence, not a word, and a new Latin language needs a word list (`LatinMarkers`); accuracy on real text beyond the fixtures and the unit sentences is not measured, the owner's hand test (task 10) is the check.
- **Engine: `OnDeviceOcrEngine`** (`engine/.../ocr`), the `OcrEngine` for the PP-OCRv5 packs and Hebrew. With a language: the installed pack that serves it reads. Without one: the Hebrew probe first if Hebrew is installed (confidence 0.8 or more is Hebrew; spike: 0.93 against 0.18 to 0.51), else detect once and let every installed PP-OCRv5 pack read the two longest lines, the most confident reads the page (strategy C of the spike). Hebrew arrives as `HebrewReader` (probe and read), implemented over Tesseract in task 7; until then Hebrew is "not available in this version".
- **The language is told among all installed languages, not those of the winning pack.** Found on the first real run: `eslav` reads English as well as `latin` and won the probe on `en-skew`, and restricting the detector to its languages answered Russian for a page that was read correctly. When the detector cannot tell, the answer is the first installed language written in the script of the text.
- **Seams for tests:** `BoxDetector`, `LineRecognizer`, `PaddleModelSource` (real: `TextDetector`, `TextRecognizer`, `PaddleModels`), so the choices are unit-tested with fakes and no ONNX. `PaddleReader` opens the detector and each recognizer once and keeps them until `close()`.
- **Empty result is a failure** ("No text was found in the image."), also with a language given; the UI shows the message as for any other failure.
- **Tests:** unit tests for the scripts, the detector (sentences in eight languages, ties, candidates), the engine (fakes) and the detector on the fixtures' expected text; `FixtureEngineTest` (opt-in, real models) reads the 10 PP-OCRv5 fixtures with and without a language: right language and 0.0 % CER on all 20 runs, 180 to 350 ms per page without a language, 85 to 150 ms with one (1.3 s for the first, loading the models).
- **Not handled:** text in two Latin languages on one page (one answer), Latin languages other than the four, a probe that fails on a photo (real photos: task 10).
