# M3: hand-test checklist and results

The owner runs this in task 11, before `/release 0.2.0`. Labels are the exact texts of the UI (read from the source on 2026-11-24). Fill in "Result" (OK, or what you saw) and "Date" per row; findings that need a change go into the Findings table at the end, and each becomes a fix or a GitHub issue before the release. The results are written into this file in the same session in which the owner reports them. What M1 and M2 covered (file dialogs, recognition, first-use download of the reading models, settings file, offline use of reading) is in `docs/manual-testing.md` and `docs/manual/m2.md`; this file covers what M3 added: choosing a target language, the route marks, the download of translation models, the translation itself, the Result screen with translation and original, and the credits.

## Before you start

- Build under test: `.\gradlew :desktopApp:run` for a first pass (the version line says "GlyphDraft dev"), the packaged zip from `.\scripts\build.ps1` or the release dry run for the final pass, and the debug APK on the emulator for section I.
- Test files and the data folder live under `C:\Vibe\z_tmp\GlyphDraftTests` (decision 0003), never in the repo and never `%TEMP%`.
- You need internet for the first download of each translation model and a way to switch it off again. Plan for about 1 GB of downloads and 10 minutes for the full pass; `he to en` alone is 370 MB, so do rows C9 and C10 last or skip them on a slow line.
- Reading models are needed as well (Settings, "Language models"): install all four first (about 50 MB), so that a missing reading pack does not mix into the translation checks. Or let the first read offer them.

```powershell
$root = "C:\Vibe\z_tmp\GlyphDraftTests"
$env:GLYPHDRAFT_DATA_DIR = "$root\data-m3"          # a fresh, empty data folder for the first-use run
$files = "$root\files"
New-Item -ItemType Directory $files -Force | Out-Null
Copy-Item C:\Vibe\GlyphDraft\engine\src\test\resources\fixtures\*.png $files
Copy-Item C:\Vibe\GlyphDraft\engine\src\test\resources\fixtures\*.txt $files
```

The environment variable lasts for that PowerShell window only. The translation models are one direction each: `en to de`, `de to en`, `en to fr`, `fr to en`, `en to es`, `es to en`, `en to ru`, `ru to en`, `en to zh`, `zh to en`, `ja to en`, `he to en`, `ru to he`. English is the hub for everything; Russian is the second hub for Hebrew as a target. So `de to fr` runs two models (via English), `de to he` four (via English and Russian), `ja to de` two (via English). Sizes in the download dialog are in MiB with the label "MB": about 108 MB for a typical direction, 360 MB for `he to en`.

Known and accepted, so not findings: machine translation makes mistakes (the automated test only shows that the reading and the translation work together; the exactness of the read, 100 on all fixtures, tells nothing about the translation); "Sylter Deich" comes out as "Sylver dike"; times in Hebrew output are written "10: 30" with a space; Chinese as a target and everything with Hebrew carry the mark "experimental".
